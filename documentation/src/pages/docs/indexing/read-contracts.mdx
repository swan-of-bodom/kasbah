# Read contracts [Call contract functions from handlers]

`context.client` reads contract state at the end of the block being handled. Results are cached once the block is
final.

```ts
const balance = await context.client.readContract({
  abi: erc20Abi,
  address: token,
  functionName: "balance_of",
  args: { account: event.args.to },
});
```

Several reads in one request, like viem's `multicall`:

```ts
const [name, symbol] = await context.client.readContracts({
  contracts: [
    { abi: erc20Abi, address: token, functionName: "name" },
    { abi: erc20Abi, address: token, functionName: "symbol" },
  ],
  allowFailure: false,
});
```

- `block`: read at another block instead.
- `call({ address, entrypoint, calldata })`: a raw call, felts in and out.

## Arguments and results

- `args` is an object by input name, typed from the ABI.
- One output is its value (`bigint` for a `u256`); several are a tuple; Cairo 0 functions return an object by name.
- With `allowFailure` left on, each entry of `readContracts` is `{ status: "success", result }` or
  `{ status: "failure", error }`.

## Caching

Reads at final blocks are cached: in memory and in Postgres, so a re-index makes no calls.
`readContracts` saves round trips, but the provider still bills each call in it.
