# Handlers [Run code for each event]

```ts [src/index.ts]
import app from "../kasbah.config.ts";

app.on("Core:Swapped", async ({ event, context }) => {
  event.args;              // decoded, typed from the ABI
  event.address;           // the contract that emitted it
  event.block.number;      // also hash; the whole header with include.block
  event.transaction.hash;
  event.index;             // position in the transaction
  event.log;               // raw keys and data

  context.db;              // read and write your tables
  context.client;          // read contracts at this block
});
```

Events are handled in chain order, one at a time. `u64` and wider integers and `felt252` are `bigint`, smaller
integers `number`. Addresses and class hashes are `0x` and 64 lowercase hex digits, so `===` compares them; `felt(x)`
gives that form for your own values.

## Setup

Runs once, before the first event, on an empty database. Use it to seed rows.

```ts
app.on("setup", async ({ context }) => {
  await context.db.insert(totals).values({ id: "all", swaps: 0 });
});
```

## FAQ

**In what order do handlers run?** By block, then transaction, then event within it, across all contracts. Block
handlers run after their block's events. One handler at a time, never in parallel.

**What happens on a reorg?** Blocks within `reorgWindow` of the head are written with an undo journal. When the
chain replaces them, their writes are undone and the new blocks are handled.

**What if the process crashes?** The next start resumes from the last committed block and undoes anything written
after it, so nothing is applied twice.

**Backfill and live?** The backfill fetches history in parallel windows up to the last final block; then the
indexer follows the head block by block. Handlers can't tell the difference.
