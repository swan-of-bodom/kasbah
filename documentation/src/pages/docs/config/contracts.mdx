# Contracts [What to index: addresses, ranges, factories and filters]

```ts [kasbah.config.ts]
contracts: {
  Core: {
    abi: coreAbi,
    address: "0x00000005dd3d2f4429af886cd1a3b08289dbcea99a294197e9eb43b0e0325b4b",
    startBlock: "deployment",
  },
},
```

The key (`Core`) names the contract in handlers: `app.on("Core:Swapped", …)`.

## Address and range

- `address`: one address, or a list sharing the ABI and handlers (`event.address` tells them apart).
- `startBlock`: a block number, or `"deployment"` to start where the contract was deployed (found by a binary
  search: about 25 calls at startup).
- `endBlock`: the last block indexed. Nothing after it is fetched.

```ts
Tokens: {
  abi: erc20Abi,
  address: ["0x…STRK", "0x…ETH"],
  startBlock: 900_000,
  endBlock: 1_000_000,
},
```

## Factories

Index every contract a factory creates: the `parameter` of each `event` it emits is a child address.

```ts
Pairs: {
  abi: pairAbi,
  factory: {
    address: "0x…",
    abi: factoryAbi,
    event: "PairCreated",
    parameter: "pair",
  },
  startBlock: "deployment",
},
```

## Filters

Only events whose arguments have these values:

```ts
filter: {
  Transfer: {
    to: "0x…",
  },
  Swapped: {
    amount: [1n, 2n],
  },
},
```

Event and argument names are checked against the ABI. A value or a list of allowed values, for plain types only:
felts, integers, `u256`, `bool`, addresses and class hashes.

- Key arguments (`#[key]`) are filtered by the node, so only matches are downloaded. Those requests skip the event
  cache.
- Data arguments are filtered after decoding: everything is downloaded.

## Transactions, receipts and block headers

```ts
include: {
  transaction: true,
  receipt: true,
  block: true,
},
```

Each one adds a field to `event` (`event.transaction`, `event.receipt`, the full `event.block` with its timestamp),
typed only when asked for. They cost an extra request per transaction or per block, cached once final.

## Upgrades

Each event is decoded with the class the contract had at that block. `upgradeEvents` names the events that announce
a new class, so the class is only read again when one is emitted. `Upgraded`, `ClassHashReplaced` and
`ImplementationReplaced` are found in the ABI by default; `[]` means the contract never upgrades.
