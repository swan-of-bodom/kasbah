# Installation [Install kasbah and its requirements]

## Requirements

- **Node.js 22.18 or later.** Your `.ts` files run with Node's type stripping, so imports need the `.ts`
  extension, and TypeScript-only syntax that emits code (`enum`, `namespace`) isn't supported.
- **TypeScript 5** for editor types and `pnpm typecheck`. ABIs must be `as const`, or nothing is typed.
- **Postgres 17**, or Docker or Podman: without `DATABASE_URL`, `dev` runs Postgres in a container for you.
- **A Starknet RPC** on spec 0.10 (Alchemy, Blast, your own Pathfinder or Juno).

## New project

:::code-group

```bash [pnpm]
pnpm create kasbah my-indexer
```

```bash [npm]
npm create kasbah@latest my-indexer
```

```bash [yarn]
yarn create kasbah my-indexer
```

:::

It asks what to start from (a contract address or a template), your RPC and a database, then writes the project,
installs it and makes it a git repository. The RPC defaults to a free public one, fine to try kasbah; for a long
backfill, use a provider's (Alchemy, Infura) or your own node. See the [quickstart](/docs/quickstart), and
`pnpm create kasbah --help` for the flags.

## Into an existing project

:::code-group

```bash [pnpm]
pnpm add kasbah
```

```bash [npm]
npm install kasbah
```

```bash [yarn]
yarn add kasbah
```

:::

Drizzle comes with it: tables and queries are imported from `kasbah` too.

## Docker

Docker (or Podman) only runs Postgres for `dev` when there's no `DATABASE_URL`. Platforms like Railway and Render
build the project from `package.json`; to run it in Docker yourself, [VPS](/docs/production/vps) has a Dockerfile and
a compose file.

## From source

To try a change to kasbah itself, build the package and install the tarball:

```bash
git clone https://github.com/swan-of-bodom/kasbah
cd kasbah && pnpm install && pnpm pack
cd ../my-indexer && pnpm add ../kasbah/kasbah-*.tgz
```

A project made by `init` from a checkout uses that tarball, so it can't be deployed until you switch it to the npm
version (`pnpm add kasbah`).
