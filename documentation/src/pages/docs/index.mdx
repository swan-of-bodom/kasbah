# What is kasbah? [A Starknet indexer you write in TypeScript and run yourself]

kasbah reads events from a Starknet node and runs your TypeScript handlers on them. The handlers write to
Postgres tables you define, and an API serves those tables.

```text
Starknet RPC ──▶ events ──▶ your handlers ──▶ Postgres ──▶ GraphQL · your endpoints
```

A project is four files:

| File | What it holds |
| --- | --- |
| `kasbah.config.ts` | the network, the RPC and the contracts to index |
| `kasbah.schema.ts` | your tables (Drizzle) |
| `src/index.ts` | event handlers |
| `src/api/index.ts` | the HTTP API, a Hono app (optional) |

It runs as one Node.js process next to Postgres, with any Starknet RPC on spec 0.10. There's no hosted service and
nothing to sign up for.

## Thanks to Ponder

kasbah stands on the work of [Ponder](https://ponder.sh), the open-source TypeScript indexer for EVM chains,
built by the Ponder team and released under the MIT license.

kasbah is written for Starknet, and its design is Ponder's: the project layout, `app.on(…)` handlers, Drizzle
tables, the read API, and many choices about running in production, such as load-balanced RPCs,
one indexer per schema and zero-downtime deploys. When we weren't sure how something should work, we looked at
how Ponder does it, and usually did the same. If you know Ponder, most of kasbah will feel familiar, and
Ponder's documentation is worth reading too. The GraphQL API and the built-in endpoints are adapted from Ponder's
code, with its MIT notice in
[THIRD_PARTY_NOTICES.md](https://github.com/swan-of-bodom/kasbah/blob/main/THIRD_PARTY_NOTICES.md).

If you index EVM chains, use Ponder. We're grateful to its authors for building it in the open and sharing what they
learned.
