# CLI [Every kasbah command and flag]

`kasbah --help` lists the commands, and `kasbah <command> --help` (or `kasbah help <command>`) prints a command's
options.

The project's `package.json` runs the commands below as scripts: `dev`, `fresh` (`kasbah dev --reset`), `clean`,
`start` and `serve` (`pnpm dev`, `npm run dev`, `yarn dev`).

## init

```bash
kasbah init [dir]
```

Creates a project, then installs its packages and makes it a git repository with one commit. Asks for whatever
isn't given as a flag. `pnpm create kasbah` (`npm create kasbah@latest`, `yarn create kasbah`) runs it and is the
recommended way: it needs nothing installed beforehand and takes the same flags.

| Flag | Description |
| --- | --- |
| `-t, --template <name>` | start from a template: `erc20`, `ekubo`, `jediswap` or `pragma` (see the [quickstart](/docs/quickstart)) |
| `--rpc <url>` | the Starknet RPC (default: `KASBAH_RPC_URL`, else a free public one, fine to try kasbah; use a provider's, such as Alchemy, for a long backfill) |
| `--address <0x…>` | the contract; its ABI and deployment block are read from the chain |
| `--name <Name>` | its name in the config, `Core` in `Core:Swapped` |
| `--handle <A,B>` | events to write handlers and tables for |
| `--start <block>` | the start block (default: its deployment) |
| `--database <url>` | a Postgres URL (default: a dev container) |
| `--timestamps` | a `timestamp` column in each table |
| `--no-ws` | poll only, no WebSocket |
| `--npm`, `--pnpm`, `--yarn` | the package manager to install with and write the project for (default: the one running `create`, else pnpm) |
| `--skip-install` | don't install the packages |
| `--skip-git` | don't make a git repository (inside one already, it never does) |
| `-y, --yes` | take the defaults, ask nothing |
| `-h, --help` | `init`'s flags |
| `-v, --version` | kasbah's version |

## dev

```bash
kasbah dev [--reset] [--no-ui] [--debug]
```

Indexes, follows the head and restarts on every file change. A new [build](/docs/database#builds) drops the old
data; an API or settings change keeps it, and the restart resumes from the last block. Without
`DATABASE_URL`, runs Postgres in a container. `--reset` drops everything first (`pnpm fresh`).

## start

```bash
kasbah start [--to <block>] [--reset]
```

The same for production: needs `DATABASE_URL` and a schema name (`--schema`), refuses data from another build and a
schema another indexer is running on. `--to` stops at that block.
Ctrl-C or `SIGTERM` finishes the current block and exits (during startup, it stops at once); a third one exits at
once. The dashboard then shows the run as stopped, with the block it committed through.

## serve

```bash
kasbah serve
```

The API only, over what a `start` with the same schema stores.

## clean

```bash
kasbah clean [--yes]
```

Deletes the dev container and its volume, or with `DATABASE_URL`, only the app's schema. Asks first, unless
`--yes`. The cache stays.

## list

```bash
kasbah list [--database <url>]
```

With `DATABASE_URL` (or `--database`), the app schemas in that database, largest first: whether an indexer is running
on it, whether `dev` or `start` made it, its phase, last block, table count, size and when it was last active; then the
size of each chain's event cache. With a schema per deploy, it shows which old ones you can drop. Without
`DATABASE_URL`, the same for each running dev container (a stopped one shows its schemas once `dev` starts it).

Then every dev database on the machine, the Postgres containers `dev` made for apps without `DATABASE_URL`: whether
it is running, its port, the size of its volume and the app directory it belongs to. Containers an older kasbah made
show no directory: `kasbah clean` in their app and the next `dev` makes one that does. It doesn't read the app, so it
runs from anywhere.

## prune

```bash
kasbah prune [--yes] [--database <url>]
```

Drops every app schema in `DATABASE_URL` that no indexer is running, after listing them and asking (`--yes` to skip
the question). A schema whose indexer starts meanwhile is kept. The event caches stay, so a new deploy still
re-indexes without fetching again. A dev container is deleted with `kasbah clean` instead.

## cache

```bash
kasbah cache clear [--events] [--calls] [--chain <id>]
```

Empties the shared cache of raw events and contract reads, per chain. `kasbah list` shows each chain's cache and its
size.

## Common flags

| Flag | Env | Default |
| --- | --- | --- |
| `--schema <name>` | `DATABASE_SCHEMA` | the config's; for `dev` and `clean`, else the directory's name; **required** for `start` and `serve` |
| `--port <n>` | `PORT` | `42069` |
| `--hostname <host>` | `API_HOST` | `localhost` |
| `--ui` / `--no-ui` | | on for `dev` in a terminal |
| `--debug` | | off; with the progress screen, adds the fetcher's buffer and windows, its waits and the event loop's delay |

Every command reads `.env` from the working directory. Variables already set win.
