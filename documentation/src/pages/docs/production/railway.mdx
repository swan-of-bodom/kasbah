# Railway [Deploy with a Railway Postgres]

::::steps

### Push your project to GitHub

Railway builds it from `package.json`: no Dockerfile needed.

### Create the service

In Railway: **New Project → Deploy from GitHub repo**, and pick it.

### Add Postgres

**Create → Database → Add PostgreSQL**.

### Set the variables

On the indexer service, **Variables**:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | **Add Reference → Postgres → `DATABASE_URL`** |
| `KASBAH_RPC_URL` | your RPC URL |

`PORT` is set by Railway and used automatically.

### One schema per deploy

**Settings → Deploy → Custom Start Command**:

```bash
pnpm start --schema $RAILWAY_DEPLOYMENT_ID
```

Each deploy indexes into its own schema while the old one keeps serving.

### Health check

**Settings → Deploy → Healthcheck Path**: `/ready`, and **Healthcheck Timeout**: `3600` (the most Railway allows).
Traffic moves to a new deploy only once it's caught up. A backfill longer than an hour fails the deploy; later
deploys re-index from the event cache, so they fetch nothing already fetched.

### Get a URL

**Settings → Networking → Generate Domain**. Then open `https://<domain>/graphql`.

::::

Old schemas stay in the database. `kasbah list` shows them with their sizes; `kasbah prune` drops every one no
indexer is running, or `kasbah clean --schema <id> --yes` drops one.

A repository with a `Dockerfile` is built from it instead, and Railway then runs the start command without a shell,
so `$RAILWAY_DEPLOYMENT_ID` stays as written. Wrap it:
`/bin/sh -c "exec pnpm start --schema $RAILWAY_DEPLOYMENT_ID"`.
