# VPS [Docker Compose and Caddy on your own server]

Postgres and the indexer in Docker Compose: health-checked, restarted on failure, the API on `127.0.0.1:42069`
only, with Caddy in front.

::::steps

### Add the Docker files

In the project, next to `package.json`:

```dockerfile [Dockerfile]
FROM node:24-slim
RUN npm install -g pnpm@10
WORKDIR /app
COPY . .
RUN pnpm install --frozen-lockfile
EXPOSE 42069
# kasbah itself, not through the package manager: it gets the SIGTERM of a stop and finishes the block it's on.
CMD ["node", "node_modules/kasbah/dist/cli/main.js", "start"]
```

With npm, drop the `npm install -g` line and run `npm ci`; with Yarn, `RUN corepack enable` and `yarn install`.

```text [.dockerignore]
node_modules
.env
.git
```

```yaml [docker-compose.yml]
services:
  postgres:
    image: docker.io/library/postgres:17
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-kasbah}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "postgres"]
      interval: 5s
    restart: unless-stopped

  indexer:
    build: .
    env_file: .env
    environment:
      DATABASE_URL: postgres://postgres:${POSTGRES_PASSWORD:-kasbah}@postgres:5432/postgres
      # start needs one: a new one when the build changes (config, tables or handlers).
      DATABASE_SCHEMA: ${DATABASE_SCHEMA:-my_indexer}
    # Localhost only: Caddy in front for the outside, with TLS.
    ports:
      - "127.0.0.1:42069:42069"
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:42069/health').then((r) => process.exit(r.ok ? 0 : 1), () => process.exit(1))"]
      interval: 30s
      start_period: 30s
    stop_grace_period: 30s
    restart: unless-stopped

volumes:
  pgdata:
```

### Copy the project to the server

```bash
git clone https://github.com/you/my-indexer && cd my-indexer
```

### Set the variables

```bash [.env]
KASBAH_RPC_URL=https://…
POSTGRES_PASSWORD=a-long-random-password
DATABASE_SCHEMA=my_indexer
```

### Start it

```bash
docker compose up -d --build
docker compose logs -f indexer
```

### Put Caddy in front

Caddy gets a TLS certificate for your domain and forwards to the API:

```text [/etc/caddy/Caddyfile]
api.example.com {
  reverse_proxy 127.0.0.1:42069
}
```

```bash
sudo systemctl reload caddy
```

## Updating

```bash
git pull
docker compose up -d --build
```

The old container finishes its block and stops; the new one resumes. If the build changed, set a new
`DATABASE_SCHEMA` first: `start` refuses the old schema, and the new one indexes from scratch (or from the cache).
